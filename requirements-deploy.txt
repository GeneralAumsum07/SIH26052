# Deployment / target board (Raspberry Pi, aarch64). Inference only.
#
# This is NOT requirements.txt. That file is the x86_64 + CUDA training environment: it pins a
# CUDA 12.8 torch build, carries hashes resolved for Windows and Linux x86_64 only, and includes the
# ASR evaluation stack. On an ARM board every one of those is wrong - the hashes cannot match a
# different architecture, there is no aarch64 CUDA wheel, and nothing on a board needs faster-whisper.
#
# The DSP front end (vaani/dsp/) is numpy-only by construction, and vaani/dsp/stft.py falls back when
# torch is absent, so the board runs the exported ONNX graph with no deep-learning framework at all.
# See scripts/board_timing.py, scripts/capture_loop.py, deploy/CONTRACT.md and deploy/PI_SETUP.md.
#
#   bash scripts/pi_setup.sh                 # venv (PEP 668 safe) + this file + alsa-utils check
#   .venv-board/bin/python scripts/board_timing.py deploy/r7/cascade.onnx --seconds 30 --out deploy/board_timing.json
#   .venv-board/bin/python scripts/capture_loop.py --device hw:0,0 --out-device plughw:1,0
#
# Versions are the uv.lock resolution (the tested desktop environment). uv.lock lists cp312
# manylinux aarch64 wheels for numpy, onnxruntime, numba and llvmlite at these versions, so the board
# should run Python 3.12 (pi_setup.sh gets one through uv when the system Python differs).
# Unverified on board: no install or run on a Pi has been recorded yet.
numpy==2.5.3
onnxruntime==1.30.0
# onnxruntime's own dependencies, pinned to the same lock so the board resolves what was tested
flatbuffers==25.12.19
packaging==26.3
protobuf==7.36.2
# Required for live use, not optional. Without it vaani/dsp/nlms.py falls back to the pure-Python
# reference loop, which costs ~10.5 ms of the 16 ms hop on a desktop core (0.07 ms with numba) and
# several times that on a Pi, so scripts/capture_loop.py refuses to run live without it. The first
# call JIT-compiles the kernel (cached on disk afterwards).
numba==0.67.0
llvmlite==0.49.0
