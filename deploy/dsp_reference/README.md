# DSP golden vectors

For the shipping r7 cascade (`deploy/r7/cascade.onnx`) use **`vectors_cascade/`**, generated from the
tracked checkpoint with:

```bash
uv run --with numba python scripts/make_golden_vectors.py --checkpoint results_r2/runs/r7_e256_wr64_refiner/best.pt --onnx deploy/r7/cascade.onnx
```

Its `config.json` records the exact DSP/controller settings read from the checkpoint, plus provenance:
`checkpoint` + `checkpoint_sha256` (`121f0c3d...`), `onnx` + `onnx_sha256` (`e67a2c42...`), `git_sha` (HEAD
at generation) and `git_dirty_dsp` (whether `vaani/dsp/` had uncommitted edits then).
`tests/test_golden_vectors.py` checks both hashes against the tracked files.
It enables the limiter, blocking matrix and differential-jump rule, and includes
the limited `mix` alongside the other arrays. Match `mix` to 1e-4 as well. The
burst case exercises limiter engagement; a quiet lead-in followed by near-mouth
speech in `speech_onset` exercises blocking adaptation. Tests replay both configurations.

r7 uses the same DSP settings as Tier 4.6, so retargeting from `runs/vaani_tier46_refiner/best.pt`
left every array and wav sample unchanged; only `config.json` changed. These vectors cover the DSP
front end only (`pipeline.run`); the network's own parity is `vaani/export.py::parity_and_timing`.
The instructions below describe the preserved **legacy r1/r2** vector set.

Generated by:

```
uv run python scripts/make_golden_vectors.py
```

Each case is a 0.5 s, 16 kHz stereo clip (`vectors/<case>.wav`, float32) plus the
reference `pipeline.run()` output (`vectors/<case>.npz`: `n_hat`, `features`,
`gate`, `burst`, `reliability`), seeded with `np.random.default_rng(42)` so
regeneration is deterministic.

Use these to check a C/embedded port against the Python reference
(`vaani/dsp/features.py`, `controller.py`, `nlms.py`, `pipeline.py`).
`pipeline.run` is a single causal pass: NLMS block k is gated by `gate[k-1]`
(1.0 for k=0), its health feeds features for frame k, and the controller's
`gate[k]` from frame k gates block k+1 -- exactly the streaming order the
embedded port runs, so `n_hat` here needs no non-causal replay to match.

Tolerance: match `n_hat` and `features` to within `1e-4` absolute (float32
reference, accumulation-order differences in the C port are expected to stay
well under this); `gate`/`burst`/`reliability` must match exactly since they
come from discrete threshold logic and both sides consume the same causal
per-frame ordering.

## 2026-09-20 change (vectors regenerated)

- `features[0]` (`log_energy_delta`) is now the **sub-frame onset jump**: the newest 256-sample hop split
  into 64-sample (4 ms) blocks, `10*log10(max block energy / median of the previous 25 block energies)`.
  The history is seeded with frame 0's mean block energy.
- `features[5]` (`speech_presence`) is now measured **relative to a tracked inter-mic ratio floor**
  (`ratio_floor`: +0.002/frame up, 0.3/frame down, capped at 3 dB) with fast attack / 0.85 release:
  `sp = clip((ratio_db - floor - 2)/4, 0, 1); sp_smooth = max(sp, 0.85*sp_smooth)`.
- Controller `speech_freeze` is 0.5.
Port these three exactly; the vectors will not match otherwise.
